* Development record schema version 1
:PROPERTIES:
:CUSTOM_ID: development-record-schema-version-1
:END:
A Vela development record captures one implementation episode as deterministic, reviewable JSON. The Rust types in =vela_dev::record= are the schema authority. Unknown fields, unsupported schema versions, and values outside the bounded enums are rejected during deserialization; cross-field rules are reported separately by semantic validation.

** Shape
:PROPERTIES:
:CUSTOM_ID: shape
:END:
#+begin_src json
{
  "schema_version": 1,
  "task": {
    "title": "Validate records",
    "objective": "Reject invalid evidence",
    "acceptance_criteria": ["valid records pass"]
  },
  "attempts": [{
    "summary": "Implemented validation",
    "outcome": "success",
    "diagnostic": null,
    "patch": "crates/vela-dev/src/record.rs"
  }],
  "outcome": {
    "summary": "Validation works",
    "verified": true,
    "verification": [{"command": "just verify", "status": "passed"}]
  },
  "lessons": ["Keep validation deterministic"],
  "provenance": {
    "repository_path": "crates/vela-dev/src/record.rs",
    "url": "https://github.com/Knosence9/project-vela"
  },
  "sanitation": {"passed": true, "blockers": []},
  "trust": "curated",
  "example": {"type": "positive", "rejection_rationale": null}
}
#+end_src

Bounded values are:

- =attempts[].outcome=: =success=, =failure=, or =blocked=
- =outcome.verification[].status=: =passed=, =failed=, or =not_run=
- =trust=: =untrusted=, =reviewed=, or =curated=
- =example.type=: =positive= or =negative=

Version 1 requires non-empty task title, objective, and acceptance criteria. A verified outcome needs a passing verification. Curated evidence cannot end with a failed verification. Negative examples need an attempt diagnostic or rejection rationale. Repository paths are relative and cannot traverse parent directories, provenance URLs use HTTPS, and obvious secrets and absolute home-directory paths are rejected. Sanitation cannot pass with unresolved blockers.

** Validation CLI
:PROPERTIES:
:CUSTOM_ID: validation-cli
:END:
#+begin_src sh
nix develop --command cargo run --locked -p vela-dev -- record validate path/to/record.json
#+end_src

Exit status is =0= for valid records, =1= for records with semantic issues, and =2= for unreadable or malformed records. Semantic diagnostics are written to stderr as =<field path>: <stable code>: <message>= and all detected issues are emitted in deterministic traversal order.

** Corpus storage and inspection
:PROPERTIES:
:CUSTOM_ID: corpus-storage-and-inspection
:END:
Curated, project-native records are stored as JSON below =corpus/development/=. The corpus inspector recursively discovers =.json= files and processes them in sorted relative-path order:

#+begin_src sh
nix develop --command cargo run --locked -p vela-dev -- corpus inspect corpus/development
#+end_src

Valid entries are listed on stdout before a final count. Human-readable relative paths use one quoted, debug-escaped field, so untrusted filename controls cannot create extra output lines or terminal effects and distinct non-UTF-8 filename bytes remain distinguishable on Unix. Record-level read, deserialization, and semantic failures are prefixed with that same escaped path field on stderr; inspection continues so the summary covers the whole corpus. Exit status is =0= when every discovered record is valid, =1= when any record is invalid, and =2= when the corpus root cannot be traversed.

** Deterministic corpus sampling
:PROPERTIES:
:CUSTOM_ID: deterministic-corpus-sampling
:END:
Select a bounded path-ordered sample only after validating every discovered record:

#+begin_src sh
nix develop --command cargo run --locked -p vela-dev -- corpus sample corpus/development 32
nix develop --command cargo run --locked -p vela-dev -- corpus sample corpus/development 32 --trust curated
nix develop --command cargo run --locked -p vela-dev -- corpus sample corpus/development 32 --example negative
nix develop --command cargo run --locked -p vela-dev -- corpus sample corpus/development 32 --attempt-outcome failure
#+end_src

The required limit is from =1= through =1024=. The optional =--trust= filter accepts exactly =untrusted=, =reviewed=, or =curated=; =--example= accepts exactly =positive= or =negative=; and =--attempt-outcome= accepts exactly =success=, =failure=, or =blocked=. An attempt-outcome filter matches a record when at least one =attempts[]= entry has that exact outcome; records without attempts do not match. Present filters compose conjunctively. Success emits one compact JSON array containing each selected relative =path= and complete =record=; an empty match emits =[]=. Selection uses sorted relative-path order, applies the limit after filtering, and never reads randomness or ambient state.

Sampling emits no partial stdout. An unreadable corpus root exits with status =2=. An unreadable record, malformed JSON, semantic validation failure, or non-UTF-8 relative record path exits with status =1= after deterministic diagnostics prefixed by the same quoted, debug-escaped path field used by inspection. Discovery neither follows symbolic links nor treats non-regular =.json= entries as records; Unix reads reject candidates replaced by a final symbolic link or non-regular entry while accepting replacements that remain regular files. Sampling is read-only and performs no scoring, indexing, network access, or mutation.
