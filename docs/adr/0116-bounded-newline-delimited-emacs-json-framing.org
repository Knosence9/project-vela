* ADR-0116: Bounded newline-delimited Emacs JSON framing
:PROPERTIES:
:CUSTOM_ID: adr-0116-bounded-newline-delimited-emacs-json-framing
:END:
- *Status:* accepted
- *Date:* 2026-08-09
- *Decision and execution issue:* [[https://github.com/Knosence9/project-vela/issues/1045][#1045]]
- *Related:* [[file:0108-main-thread-authoritative-emacs-agent-interface.org][ADR-0108]], [[file:0115-bounded-in-process-emacs-json-adapter.org][ADR-0115]]

** Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
ADR-0115 defines one strict character-bounded JSON decode/dispatch/encode adapter, while requiring any future transport to establish a byte bound before decoding. A process filter can receive part of one request, several requests together, or a UTF-8 character split between chunks. Letting each transport invent accumulation, delimiters, text decoding, and overload behavior would recreate ambiguity immediately before the shared codec.

Opening a socket or subprocess now would also select peer authentication, lifecycle, error delivery, queueing, and ownership policy. None of those authorities is needed to make raw local byte chunks finite and deterministic.

** Decision
:PROPERTIES:
:CUSTOM_ID: decision
:END:
Keep protocol version 7 because no semantic operation or response shape changes. Add public pure helper =vela-agent-json-frame-feed(pending, chunk)=. Both inputs must be unibyte Emacs strings. The caller owns the exact unconsumed =pending= bytes; each call returns an ordered object containing a vector of decoded =frames= and an unibyte =remainder=.

LF is the sole frame delimiter. One CR immediately before LF is removed for CRLF interoperability. Frames must be non-empty after that removal. Each raw span before LF, including an optional CR, and each partial remainder is capped at 262,144 bytes. A chunk is capped at 4,456,464 bytes: sixteen maximum spans and delimiters followed by one maximum partial frame. One call accepts at most sixteen complete frames and rejects a seventeenth rather than returning a partially accepted result.

A complete frame is decoded as canonical UTF-8 only after its byte bound is established. Emacs-preserved raw eight-bit characters, invalid sequences, and representations that do not survive an exact UTF-8 decode/encode round trip fail as =vela-agent-protocol-error=. A multibyte character may be split across calls because only complete frames are decoded. Decoded strings remain subject to the independent 262,144-character codec input bound when a later owner-thread callback passes them to =vela-agent-handle-json=.

The helper only frames bytes. It does not parse or dispatch JSON, mutate caller state, keep a queue, schedule a timer or callback, open or control a process or socket, select a peer, authenticate, encode responses, grant editor access, or add mutation authority.

** Alternatives considered
:PROPERTIES:
:CUSTOM_ID: alternatives-considered
:END:
*** Parse every process-filter chunk as JSON
:PROPERTIES:
:CUSTOM_ID: parse-every-process-filter-chunk-as-json
:END:
Rejected because process chunks are not message boundaries and may split either a JSON value or a UTF-8 sequence.

*** Use brace counting
:PROPERTIES:
:CUSTOM_ID: use-brace-counting
:END:
Rejected because strings and escapes make ad hoc structural framing error-prone, while the existing strict JSON decoder should remain the single syntax authority.

*** Add JSON-RPC content-length headers
:PROPERTIES:
:CUSTOM_ID: add-json-rpc-content-length-headers
:END:
Deferred because envelope IDs, methods, notifications, header parsing, and error responses are transport contract decisions. Newline framing is sufficient for the current one-object JSON shape and does not imply JSON-RPC.

*** Open a local socket now
:PROPERTIES:
:CUSTOM_ID: open-a-local-socket-now
:END:
Rejected for this slice because filesystem or network namespace, permissions, peer credentials, startup/shutdown, backpressure, and error delivery need a separate explicit authority contract.

** Consequences
:PROPERTIES:
:CUSTOM_ID: consequences
:END:
- Later local transports can reuse one tested byte accumulator before invoking the strict JSON codec.
- UTF-8 sequences may cross arbitrary chunk boundaries without decoding partial input.
- Empty, oversized, over-batched, multibyte-input, and invalid-UTF-8 feeds fail closed.
- The caller remains responsible for retaining the returned remainder and for treating any error as rejection of the complete feed.
- There is still no external transport or asynchronous request queue.

** Verification
:PROPERTIES:
:CUSTOM_ID: verification
:END:
RED→GREEN ERT coverage pins partial and multiple frames, arrival order, CRLF, a UTF-8 character split between chunks, invalid and non-canonical UTF-8, empty frames, partial and complete oversize rejection, the sixteen-frame feed limit, and unibyte-only inputs. Batch byte compilation rejects warnings, and the complete repository quality gate must remain green.

** Revisit when
:PROPERTIES:
:CUSTOM_ID: revisit-when
:END:
Revisit before a transport opens or controls processes or sockets, selects peers or authentication, stores queue state, schedules editor callbacks, defines response framing and errors, adds JSON-RPC envelopes, or grants any mutation authority.
