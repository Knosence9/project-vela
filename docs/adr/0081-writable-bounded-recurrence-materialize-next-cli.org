* ADR-0081: Writable bounded recurrence materialize-next CLI
:PROPERTIES:
:CUSTOM_ID: adr-0081-writable-bounded-recurrence-materialize-next-cli
:END:
- *Status:* accepted
- *Date:* 2026-08-06
- *Decision and execution issue:* [[https://github.com/Knosence9/project-vela/issues/957][#957]]
- *Related:* ADR-0050, ADR-0079, ADR-0080

** Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
ADR-0080 establishes one bounded kernel mutation that selects the earliest available due coordinate in an exact caller-selected recurrence window and atomically binds it to a caller-owned task. The CLI exposes the parallel claim-next boundary, but automation that does not need a recoverable claim gap would otherwise require a custom adapter.

** Decision
:PROPERTIES:
:CUSTOM_ID: decision
:END:
Add =vela-dev recurrence materialize-next DATABASE RECURRENCE_ID START_OFFSET PAGE_SIZE CUTOFF_UNIX_MILLIS TASK_ID=.

The adapter validates the exact recurrence identity, positive at-most-1024 page size, and exact caller-owned task identity before storage access. It opens only the selected database through writable =RecurrenceStore::open=, converts the explicit cutoff to an inclusive caller-owned =ScheduleInstant=, and delegates selection, strict complete-window replay, optimistic race handling, and atomic occurrence/task mutation to =RecurrenceStore::materialize_next_available_occurrence=.

Success emits compact JSON with =occurrence= and =next_offset=. A materialized object preserves exact recurrence ID, goal, authored offset, instant, definition revision, resulting occurrence revision, and task ID. A null occurrence retains the kernel cursor for a future horizon, an all-gap or consumed window, or finite completion.

Invalid identities and page sizes emit =invalid_recurrence_id=, =invalid_occurrence_page_size=, or =invalid_task_id= before storage access. Missing definitions and out-of-range starts emit =recurrence_not_found= and =recurrence_occurrence_out_of_range=. Open, strict replay, selected-window corruption, task collision, contention exhaustion, append, read-only, and serialization failures emit =recurrence_occurrence_materialize_next_failed=. Every failure is non-zero, emits no stdout, and leaves no partial recurrence/task transition.

The adapter reads no ambient clock, persists no cursor, scans no unrelated recurrence, generates no identity, and grants no worker, lease, expiry, dispatch, retry-of-work, workflow, provider/tool, permission, or execution authority.

** Alternatives considered
:PROPERTIES:
:CUSTOM_ID: alternatives-considered
:END:
*** Compose available paging and exact materialization in the CLI
:PROPERTIES:
:CUSTOM_ID: compose-available-paging-and-exact-materialization-in-the-cli
:END:
Rejected because it would duplicate the kernel's ordering, future-cursor, complete-window race, contention, and atomicity policy.

*** Claim before every materialization
:PROPERTIES:
:CUSTOM_ID: claim-before-every-materialization
:END:
Rejected because a durable claim is useful only when callers need an explicit recovery gap. Direct atomic materialization is an accepted separate authority.

*** Select across recurrence definitions or generate task identities
:PROPERTIES:
:CUSTOM_ID: select-across-recurrence-definitions-or-generate-task-identities
:END:
Rejected because no bounded global ordering exists and identity allocation remains caller authority.

** Consequences
:PROPERTIES:
:CUSTOM_ID: consequences
:END:
- Automation can atomically consume one deterministic due coordinate with one bounded command.
- Sparse, released, future, consumed, and finite windows retain the kernel cursor contract.
- Task collisions, storage failures, and lifecycle races cannot create orphan tasks or partial transitions.
- Cross-recurrence discovery, durable cursors, workers, dispatch, and execution remain deferred.

** Verification
:PROPERTIES:
:CUSTOM_ID: verification
:END:
RED→GREEN CLI integration tests prove deterministic escaped projection, sparse and released selection, future and all-gap progress, finite completion, validation before storage, missing and out-of-range failures, task-collision atomicity, selected corruption, read-only rejection, and empty stdout on failures. The complete repository quality gate must remain green.

** Revisit when
:PROPERTIES:
:CUSTOM_ID: revisit-when
:END:
Reconsider before adding cross-recurrence selection, durable cursors, ambient clocks, generated identities, workers, leases or expiry, dispatch, retries, permissions, providers/tools, workflows, or execution.
