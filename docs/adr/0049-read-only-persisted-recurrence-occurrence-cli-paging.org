* ADR-0049: Read-only persisted recurrence occurrence CLI paging
:PROPERTIES:
:CUSTOM_ID: adr-0049-read-only-persisted-recurrence-occurrence-cli-paging
:END:
- *Status:* accepted
- *Date:* 2026-08-03
- *Decision and execution issue:* [[https://github.com/Knosence9/project-vela/issues/887][#887]]
- *Related:* ADR-0045, ADR-0047, ADR-0048

** Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
ADR-0048 provides bounded exact-recurrence paging over sparse durable occurrence provenance. Operators can inspect one exact coordinate through ADR-0047, but inspecting a range still requires one command per authored offset. A global inventory would broaden discovery, allocation, ordering, and corruption scope beyond the existing kernel boundary.

The smallest responsible adapter accepts one caller-selected recurrence and authored offset window, validates bounded work before storage access, and delegates the page semantics directly to the kernel.

** Decision
:PROPERTIES:
:CUSTOM_ID: decision
:END:
=vela-dev recurrence persisted DATABASE RECURRENCE_ID START_OFFSET PAGE_SIZE= validates =RECURRENCE_ID= through =RecurrenceId= and =PAGE_SIZE= through =OccurrencePageSize= before storage access. It opens only the selected existing database through =RecurrenceStore::open_read_only= and delegates directly to =RecurrenceStore::persisted_occurrences_page=.

Success emits one compact JSON object. Its =occurrences= array contains only durable coordinates from the selected authored window in ascending offset order. Every element preserves exact =recurrence_id=, =goal=, =offset=, =unix_millis=, and =definition_revision=. Missing coordinates are omitted, so an all-gap window emits an empty array. =next_offset= is the first uninspected authored offset, or =null= after the finite end.

Invalid IDs and zero or oversized page sizes emit =invalid_recurrence_id= and =invalid_occurrence_page_size= before storage access. A missing definition emits =recurrence_not_found=; an invalid start emits =recurrence_occurrence_out_of_range=. Storage open, exact replay, selected-window validation, paging infrastructure, and serialization failures emit =persisted_recurrence_occurrence_lookup_failed=. Every failure returns non-zero, emits one escaped diagnostic, and emits no stdout. Missing storage remains missing.

The command is read-only and inert. It reads no clock, persists no cursor or lifecycle evidence, and grants no global discovery, catch-up, due, materialization, claim, permission, dispatch, retry, or execution authority.

** Alternatives considered
:PROPERTIES:
:CUSTOM_ID: alternatives-considered
:END:
*** Reuse =recurrence occurrences=
:PROPERTIES:
:CUSTOM_ID: reuse-recurrence-occurrences
:END:
Rejected because that command projects every authored coordinate whether or not durable provenance exists. Combining projected and persisted evidence would blur materially different semantics.

*** Add a global persisted-occurrence inventory
:PROPERTIES:
:CUSTOM_ID: add-a-global-persisted-occurrence-inventory
:END:
Rejected because global discovery requires new ordering, pagination, indexing, and corruption-domain decisions. Exact-recurrence authored windows already provide a finite deterministic boundary.

*** Reimplement sparse paging in the CLI
:PROPERTIES:
:CUSTOM_ID: reimplement-sparse-paging-in-the-cli
:END:
Rejected because ADR-0048 already owns cursor, bounds, replay, and corruption-isolation semantics. A second implementation could diverge.

** Consequences
:PROPERTIES:
:CUSTOM_ID: consequences
:END:
- Operators can inspect sparse durable recurrence provenance with one bounded command.
- Empty windows advance deterministically without fabricating occurrence evidence.
- Projected and persisted occurrence commands remain explicitly distinct.
- Global inventory, persisted cursors, catch-up policy, materialization, dispatch, and execution remain deferred.

** Verification
:PROPERTIES:
:CUSTOM_ID: verification
:END:
Strict RED→GREEN CLI tests prove sparse deterministic JSON, all-gap cursor progress, final-page truncation, exact string escaping, validation before storage access, missing storage and definitions, out-of-range starts, selected-window fail-closed corruption, and isolation from unrelated or out-of-window corruption. The complete repository quality gate must remain green.

** Revisit when
:PROPERTIES:
:CUSTOM_ID: revisit-when
:END:
Reconsider before adding global persisted-occurrence discovery, persisted cursors, mutable recurrence lifecycle, catch-up or missed-run policy, generated identities, schedule/task materialization, workers, ambient clocks, dispatch, or execution.
