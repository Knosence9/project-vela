* ADR-0076: Bounded available recurrence occurrence paging
:PROPERTIES:
:CUSTOM_ID: adr-0076-bounded-available-recurrence-occurrence-paging
:END:
- *Status:* accepted
- *Date:* 2026-08-05

** Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
Persisted occurrence paging exposes canonical provenance but not the current lifecycle revision required by claiming or materialization after a release. Exact available-state lookup requires callers to already know each coordinate. Recovery and operator surfaces therefore lack a bounded way to discover currently available persisted coordinates and their exact optimistic-concurrency evidence.

The existing persisted, materialized, and claimed page boundaries establish an allocation-bounded, resumable model: inspect one authored-offset window, filter by strict current lifecycle state, and advance by inspected authored coordinates rather than result density. Reusing that model avoids an unbounded inventory while preserving sparse deterministic progress.

** Decision
:PROPERTIES:
:CUSTOM_ID: decision
:END:
Add =RecurrenceStore::available_occurrences_page(id, start_offset, page_size)=. The operation strictly loads one exact immutable recurrence definition, projects at most the existing validated =OccurrencePageSize= authored coordinates, and strictly replays every present occurrence stream in that selected window.

The result contains complete =AvailableRecurrenceOccurrence= values only for coordinates whose current lifecycle state remains available: persisted-only or explicitly released after complete claim/release cycles. Each value preserves the authoritative occurrence, exact current occurrence revision, and optional latest caller-authored release evidence. Claimed and materialized coordinates are omitted. =next_offset= identifies the first uninspected authored coordinate or finite completion, so valid all-gap pages still advance deterministically.

Missing recurrence definitions and out-of-range starts preserve existing typed failures. Malformed or impossible evidence in the selected window fails closed before any partial page is returned. Unrelated recurrence streams and coordinates outside the selected authored window are not inspected and cannot block a valid page.

The operation works through read-only storage, reads no clock, mutates nothing, persists no cursor, and grants no global discovery, claim-next selection, generated identity, worker identity, lease, dispatch, retry, permission, workflow, provider/tool, or execution authority.

** Alternatives considered
:PROPERTIES:
:CUSTOM_ID: alternatives-considered
:END:
*** Add current revisions to persisted provenance pages
:PROPERTIES:
:CUSTOM_ID: add-current-revisions-to-persisted-provenance-pages
:END:
Rejected because persisted paging intentionally exposes every valid durable coordinate regardless of lifecycle. Changing that result would mix canonical provenance with current availability and still require lifecycle filtering by every caller.

*** Return only released coordinates
:PROPERTIES:
:CUSTOM_ID: return-only-released-coordinates
:END:
Rejected because persisted-only coordinates are equally available. A claimable inventory must include both available forms while distinguishing optional recovery evidence.

*** Select or claim the next available coordinate
:PROPERTIES:
:CUSTOM_ID: select-or-claim-the-next-available-coordinate
:END:
Rejected because mutation and contention introduce a separate authority boundary. This slice supplies bounded read evidence only.

** Consequences
:PROPERTIES:
:CUSTOM_ID: consequences
:END:
- Callers can inspect exact current revisions needed for later explicit claim or materialization attempts.
- Persisted-only coordinates carry no fabricated release evidence; released coordinates preserve only their latest caller-authored recovery reason.
- Claims and materializations disappear from subsequent available pages without rewriting earlier evidence.
- Global inventory and claim-next mutation remain separate future boundaries.

** Verification
:PROPERTIES:
:CUSTOM_ID: verification
:END:
Strict RED→GREEN integration tests cover sparse mixed lifecycle filtering, exact revisions, latest release evidence, all-gap and finite cursor behavior, read-only reopen, missing definitions, out-of-range starts, and selected-window corruption isolation. The complete repository quality gate must remain green.

** Revisit when
:PROPERTIES:
:CUSTOM_ID: revisit-when
:END:
Reconsider before adding CLI exposure, cross-recurrence available inventory, claim-next selection, durable cursors, generated task identity, workers, leases or expiry, ambient clocks, dispatch, retries, permissions, or execution.
