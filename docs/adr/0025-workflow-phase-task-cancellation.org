* ADR-0025: Preserve explicit workflow-phase final responses as task cancellation attempts
:PROPERTIES:
:CUSTOM_ID: adr-0025-preserve-explicit-workflow-phase-final-responses-as-task-cancellation-attempts
:END:
- *Status:* accepted
- *Date:* 2026-07-30
- *Decision and execution issue:* [[https://github.com/Knosence9/project-vela/issues/761][#761]]

** Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
ADR-0021 through ADR-0024 preserve explicit workflow-phase responses as task Attempt and Correction evidence and add caller-owned completion and failure. The task runtime also models cancellation as caller-owned terminal intent: a final provider response is Attempt evidence, while an already validated caller reason explains why execution should stop. Callers need the same narrow phase-assisted cancellation boundary without granting a model authority to invent cancellation reasons or coupling task cancellation to workflow-run lifecycle.

** Decision
:PROPERTIES:
:CUSTOM_ID: decision
:END:
=AssistantRuntime::cancel_workflow_phase_task_turn= is the explicit tool-free phase-assisted task-cancellation boundary. The caller supplies the exact active task, fresh Attempt observation ID, validated =TaskCancellation=, borrowed =RegisteredWorkflowPhase=, process-local skill registry, human content, system policy, and developer policy. The task must already be associated with a writable session.

Before transcript persistence or provider invocation, the runtime validates that the task is active and associated, the Attempt ID is fresh and legal, the associated session is writable, and the phase bindings resolve through ADR-0019. The provider then receives ADR-0020's distinct authority fields and the durable transcript after the human turn.

On a valid response, the runtime validates the exact content as Attempt text, atomically appends the assistant transcript turn and matching Attempt, then applies the caller-owned cancellation with the exact retained reason. A provider failure or blank-only response preserves the committed human turn and appends no assistant turn, Attempt, or cancellation. An authoritative failure while appending the response preserves neither assistant turn nor requested Attempt. A terminal race after that atomic append preserves the assistant turn and Attempt, returns the winning task error, and does not replace the winning terminal state.

Provider content is only Attempt evidence. It is not cancellation-reason or Verification evidence and cannot replace the validated caller-owned =TaskCancellation=. The operation applies only to the task. It does not infer or mutate a workflow run, prove phase or skill-selection provenance, acknowledge a gate, choose a transition, cancel a workflow, grant tools, or synchronize task and workflow lifecycles.

** Alternatives considered
:PROPERTIES:
:CUSTOM_ID: alternatives-considered
:END:
*** Derive the cancellation reason from the provider response
:PROPERTIES:
:CUSTOM_ID: derive-the-cancellation-reason-from-the-provider-response
:END:
A model response can explain an attempt, but stopping execution is caller-owned authority. Deriving the reason would blur execution evidence with the fact that authorized cancellation was requested.

*** Cancel an attributed workflow run with the task
:PROPERTIES:
:CUSTOM_ID: cancel-an-attributed-workflow-run-with-the-task
:END:
Workflow-run attribution is historical context, not terminal synchronization authority. Coupling both cancellations would require explicit eligibility, revisions, reasons, and partial-failure semantics beyond this bounded operation.

*** Persist the assistant turn, Attempt, and cancellation atomically
:PROPERTIES:
:CUSTOM_ID: persist-the-assistant-turn-attempt-and-cancellation-atomically
:END:
The existing terminal task runtime preserves ordered durable prefixes. Reusing that behavior keeps terminal races observable and avoids a special transaction contract for phase-assisted work.

** Consequences
:PROPERTIES:
:CUSTOM_ID: consequences
:END:
- Callers can explicitly cancel an active task after one phase-composed response.
- The exact response is durable Attempt evidence, while the exact caller reason remains terminal authority.
- Deterministic task, session, and phase errors precede provider effects.
- The assistant turn and Attempt remain atomic, while cancellation retains established ordered-prefix race semantics.
- Workflow lifecycle remains caller-owned and unchanged.

** Verification
:PROPERTIES:
:CUSTOM_ID: verification
:END:
RED→GREEN tests prove deterministic selected skills, exact durable Attempt and caller reason, duplicate-Attempt and invalid-phase rejection before provider effects, provider-failure partial-commit semantics, and preservation of the response prefix when cancellation loses a terminal race. The complete repository quality gate must remain green.

** Revisit when
:PROPERTIES:
:CUSTOM_ID: revisit-when
:END:
Reconsider this decision before adding durable phase execution identities, workflow-aware tool cancellation turns, run-derived phase selection, persisted skill-selection evidence, independent Verification capture, task/workflow terminal synchronization, automatic transitions, retries, scheduling, actors, timestamps, or remote execution.
