* ADR-0103: Bounded finite recurrence lifecycle-history paging
:PROPERTIES:
:CUSTOM_ID: adr-0103-bounded-finite-recurrence-lifecycle-history-paging
:END:
- *Status:* accepted
- *Date:* 2026-08-08
- *Decision and execution issue:* [[https://github.com/Knosence9/project-vela/issues/1011][#1011]]
- *Related:* ADR-0037, ADR-0084, ADR-0091, ADR-0101

** Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
=RecurrenceStore::history= exposes one known finite recurrence's complete typed lifecycle evidence. =RecurrenceStore::list_page= bounds global definition discovery but returns only each recurrence's current projection. An auditor that needs lifecycle evidence for discovered recurrence definitions must therefore page inventory and issue a separate exact replay for every result. Those calls do not share one read snapshot, and every caller must duplicate continuation and corruption handling.

A recurrence aggregate currently contains creation and optional cancellation evidence, but future valid lifecycle transitions could make one stream grow independently of inventory size. Paging individual events would need a separate continuation contract that can validate later events without trusting an invalid prefix. The smallest responsible boundary bounds authoritative stream selection while preserving complete fail-closed lifecycle replay for every selected recurrence.

** Decision
:PROPERTIES:
:CUSTOM_ID: decision
:END:
Add =RecurrenceHistory=, containing one exact =RecurrenceId= and its complete revision-ordered =RecurrenceHistoryEntry= values. Add =RecurrenceHistoryPage=, containing exact-ID-ordered histories and an optional =next_after= recurrence ID.

=RecurrenceStore::histories_page(after, page_size)= accepts the existing validated =RecurrencePageSize= bound from 1 through 1024. It selects at most =page_size + 1= authoritative streams marked by =recurrence.fixed_interval_created= after the optional caller-owned exclusive exact-ID cursor and fully replays those streams in one read snapshot. Every selected lifecycle, including lookahead, is canonically projected before any output is returned.

When validated lookahead proves another recurrence exists, the page removes lookahead and sets =next_after= to the last returned recurrence ID. Otherwise the cursor is absent. The cursor need not identify an existing recurrence. Empty stores and cursors beyond the end return empty terminal pages.

The operation works through read-only storage, reads no ambient clock, mutates nothing, persists no cursor, and grants no occurrence lifecycle, aggregate mutation, worker, lease, dispatch, retry, permission, or execution authority.

** Alternatives considered
:PROPERTIES:
:CUSTOM_ID: alternatives-considered
:END:
*** Page inventory and call exact history in the caller
:PROPERTIES:
:CUSTOM_ID: page-inventory-and-call-exact-history-in-the-caller
:END:
Rejected because inventory selection and exact histories would not share one read snapshot, and every caller would have to reproduce continuation and fail-closed aggregation behavior.

*** Page individual lifecycle events by revision
:PROPERTIES:
:CUSTOM_ID: page-individual-lifecycle-events-by-revision
:END:
Rejected for this slice because validating a non-initial page requires prior lifecycle state. Replaying the complete prefix would bound output but not work, while trusting caller-supplied state could accept impossible histories. A safe partial-history protocol needs a separate snapshot and state-proof decision.

*** Generalize schedule and recurrence history paging immediately
:PROPERTIES:
:CUSTOM_ID: generalize-schedule-and-recurrence-history-paging-immediately
:END:
Rejected because the aggregate event types, IDs, replay errors, and public projections remain intentionally distinct. A generic abstraction would add indirection for only two short adapters without reducing durable authority or schema.

** Consequences
:PROPERTIES:
:CUSTOM_ID: consequences
:END:
- Global recurrence selection and returned-history count are bounded by one explicit page plus lookahead.
- Replay and aggregate allocation within each selected recurrence remain proportional to that recurrence's complete lifecycle history.
- Exact goals, anchors, intervals, finite counts, cancellation reasons, and one-based revisions remain inspectable without a second storage snapshot.
- Corruption in the returned window or lookahead fails closed before partial output. Corruption before the cursor, beyond lookahead, and in unrelated stream families remains isolated.
- Existing exact history, inventory, status, and occurrence projections remain unchanged.
- No event, schema, write, clock, worker, or execution authority is added.

** Verification
:PROPERTIES:
:CUSTOM_ID: verification
:END:
Strict RED→GREEN tests prove complete active and cancelled evidence, exact-ID ordering, non-overlapping continuation, nonexistent and beyond-end cursors, empty and terminal behavior, selected and lookahead corruption failures, and isolation from corruption before the cursor, after lookahead, and in unrelated streams. The complete repository quality gate must remain green.

** Revisit when
:PROPERTIES:
:CUSTOM_ID: revisit-when
:END:
Reconsider before adding CLI exposure, partial per-stream history paging, snapshot tokens, durable cursors, lifecycle indexes, destructive deletion, clocks, workers, leases, dispatch, retries, permissions, or execution.
